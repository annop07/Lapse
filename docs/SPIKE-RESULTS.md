## S1 — เรนเดอร์ข้อความไทย

IBM Plex Sans Thai 14.5px / height 1.85 / `TextLeadingDistribution.even`

ตรวจคำที่เสี่ยงที่สุดคือคำที่มีสระบนซ้อนวรรณยุกต์ทีละคำ:
`ผู้ใหญ่` · `ตั้งใจ` · `ทั้งๆ` · `ครึ่ง` · `ชั่วโมง` · `คลื่นนิ่ง` · `พรุ่งนี้`

- สระบนกับวรรณยุกต์ซ้อนถูกตำแหน่งทุกตัว ไม่ชนกัน
- บรรทัดแรกไม่ถูกตัดหัว — `leadingDistribution: even` ทำงานตามที่ตั้งใจ
- บรรทัดไม่ซ้อนกันที่ระยะ 1.85
- การตัดคำถูกต้อง (`ควรจะ` / `เป็น` เป็นรอยต่อคำจริง)

ความเสี่ยงที่เหลือต่ำ เพราะ Flutter วาดข้อความด้วยเอนจินตัวเองและฟอนต์ที่ฝังมา
ไม่ได้ยืม text metrics ของแพลตฟอร์ม ผลบนเครื่องจริงจึงควรตรงกับ simulator
(ข้อนี้เป็นเหตุผลหนึ่งที่สเปก §6.3 เลือก Flutter แทน React Native)

## S2 — ตารางกำแพง

371 ช่อง · ช่อง 7px เว้น 2px · DPR 3

- ขอบคมสม่ำเสมอ **ทุกช่องเท่ากัน** ทั้งคอลัมน์แรกและคอลัมน์ท้าย
- ระยะห่างเท่ากันตลอดแถว ไม่มีคอลัมน์ไหนเบี้ยว
- รัศมีมุมตรงกับโทเคน `--lp-r-cell: 2px`

`snapToPixel` ทำงานตามที่ออกแบบ — ปัดพิกัดเข้าเส้นพิกเซลจริงก่อนวาด
มีเทสต์เดินครบ 53 คอลัมน์ที่ DPR 2 และ 3 ยืนยันว่าทุกขอบตกบนเส้นพิกเซลจริง

## S3 — จับเวลาและ lifecycle

### ผ่านแล้ว: การสลับไปแอปอื่น

ทดสอบ: เปิดแอป → อยู่หน้าจอ 10 วินาที → สลับไป Settings 30 วินาที → กลับเข้ามา

- **เวลาสะสม 11 วินาที ไม่ใช่ 40** — ช่วงที่ออกไปไม่ถูกนับ
- **`lastLockWindow` คืน `start=null end=null`** คือสัญญาณล็อกจอ**ไม่ยิง**ตอนสลับแอป

ข้อหลังคือสมมติฐานที่ทั้งกลไกวางอยู่บนมัน ถ้ามันยิงตอนสลับแอปด้วย วิธีนี้ตายทันที

### ลำดับ lifecycle จริงของ iOS

```
ขาออก   inactive → hidden → paused
ขากลับ  hidden → inactive → resumed
```

**`hidden` มาสองครั้ง** และครั้งที่สองมาตอนกำลังกลับเข้าแอป
การ์ด `if (!session.isRunning) return;` ใน `SessionLifecycle._onLeft` จึงรับน้ำหนักจริง
ถ้าไม่มีมัน `hidden` ครั้งที่สองจะเขียนทับเวลาที่ออกไป แล้วช่วงที่หายไปจะถูกคิดเป็นศูนย์
มีเทสต์จำลองลำดับนี้เป๊ะๆ ไว้แล้ว

### ยังไม่ผ่าน: การล็อกจอ

**ต้องใช้ iPhone จริงที่ตั้งรหัสผ่านไว้** simulator ทดสอบไม่ได้เพราะไม่มีการล็อกจอจริง
ไม่มีรหัสผ่าน และไม่มี data protection ซึ่งเป็นสัญญาณทั้งหมดที่โค้ดพึ่งอยู่

สิ่งที่ยังไม่มีใครยืนยัน:

1. `protectedDataWillBecomeUnavailable` ยิงจริงตอนล็อกจอบนเครื่องที่ตั้งรหัสผ่าน
2. ยิงเร็วพอที่จะอยู่ในกรอบ 2 วินาทีที่ `LockWindow.overlaps` เผื่อไว้
3. ล็อกจอทิ้งไว้ 10 นาทีแล้วเวลาที่ได้ตรง

### ผลข้างเคียงที่เจอ

`LAContext().canEvaluatePolicy(.deviceOwnerAuthentication)` คืนค่า **true บน simulator**
ทั้งที่ simulator ไม่มี data protection จริง เป็นผลบวกลวง

บนเครื่องจริงที่ไม่ได้ตั้งรหัสผ่านมันจะคืน false ซึ่งเป็นพฤติกรรมที่เราต้องการ
จึงยังใช้เป็นตัวตัดสินได้ แต่ต้องรู้ไว้ว่ามันวัด "ตั้งรหัสผ่านไหม" ไม่ได้วัด
"data protection ทำงานไหม" โดยตรง
