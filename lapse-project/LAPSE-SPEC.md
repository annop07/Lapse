# Lapse — สเปกโปรเจกต์ฉบับเต็ม

เวอร์ชัน 1.0 · สิงหาคม 2026

---

## 1. ภาพรวม

### 1.1 คืออะไร

Lapse คือแอปจับเวลาอ่านหนังสือแนวมินิมอลสุดขั้ว กลุ่มเป้าหมายหลักคือนักเรียนมัธยมปลาย
และนักศึกษาที่กำลังเตรียมสอบ เริ่มจากตลาดไทยแล้วขยายออกต่างประเทศ

แกนกลางของผลิตภัณฑ์คือแนวคิดเดียว: **หนึ่งวัน = หนึ่งหน้า**
ในหน้านั้นมีทั้งสิ่งที่ตั้งใจจะทำ เวลาที่ใช้ไปจริง และสิ่งที่คิดหลังอ่านจบ
ผู้ใช้ไม่เคยต้อง "บันทึก" อะไร เพราะแผนของตอนเช้ากลายเป็นบันทึกของตอนเย็นโดยอัตโนมัติ

### 1.2 ที่มา

แนวทางยืมโครงสร้างมาจาก [Skrive](https://skrive.app) (แอปไดอารี่ที่ใช้วันที่เป็นระบบจัดระเบียบเดียว
เข้ารหัสฝั่งผู้ใช้ เก็บเป็น plain text) และยืมรูปแบบ social มาจากกราฟ contributions ของ GitHub

### 1.3 คู่แข่งและตำแหน่งของเรา

| คู่แข่ง | จุดแข็งของเขา | จุดที่เราต่าง |
|---|---|---|
| **YPT (Yeolpumta)** | ห้องอ่านหนังสือสด สถิติละเอียด ครองตลาดไทย | ของเขาเป็นการแข่งแบบสด มีอันดับ กดดันขณะอ่าน · ของเราเป็นบันทึกย้อนหลัง ไม่มีอันดับ |
| **Forest** | ปลูกต้นไม้ น่ารัก กันติดมือถือ | สถิติเขาตื้น และเป็น subscription ฿125/เดือนในไทย |
| **Stuon** | อ้างตัวว่ามินิมอล แต่มี 10+ ฟีเจอร์ Pro | เขามี leaderboard และ "World Study Wars" — เราไม่มี · เขาเก็บเงินค่า active recall เราแจกฟรี |
| **Focus Timer** | บังคับคว่ำมือถือ | เราเอากลไกนี้มา แต่รวมกับ todo และ journal |

**ประโยคตำแหน่งผลิตภัณฑ์:** *"สำหรับคนที่ลอง YPT แล้วรู้สึกว่ามันเสียงดังเกินไป"*

### 1.4 หลักการ 5 ข้อ

1. **การตัดออกคือฟีเจอร์** — ทุกอย่างที่เพิ่มต้องแลกด้วยการเอาอย่างอื่นออก
2. **วันที่คือระบบจัดระเบียบเดียว** — ไม่มีโฟลเดอร์ แท็ก โปรเจกต์ หมวดวิชา ลำดับความสำคัญ
3. **ความเงียบคือสถานะปกติ** — ไม่เตือน ไม่ทวง ไม่ฉลอง ผู้ใช้เดินเข้ามาหาเสมอ
4. **ข้อมูลเป็นของผู้ใช้** — plain text อ่านออกด้วยตาเปล่า export ฟรีตลอด
5. **ไม่ตัดสินผู้ใช้** — วันว่างคือข้อเท็จจริง ไม่ใช่ความล้มเหลว

## 2. Data model

### 2.1 โครงสร้างไฟล์

```
lapse/
├── days/
│   ├── 2026-01-01.md
│   ├── 2026-01-02.md
│   └── 2026-08-18.md
└── meta.json
```

**หนึ่งวัน = หนึ่งไฟล์** ไม่มีข้อยกเว้น ไฟล์วันที่ไม่มีข้อมูลจะไม่ถูกสร้าง

### 2.2 รูปแบบไฟล์รายวัน

```markdown
- [x] อ่านเลข บทที่ 4 [1:47]
- [x] ท่องศัพท์ 50 คำ [0:32]
- [ ] สรุปฟิสิกส์

---
เช้าสมาธิดีมาก บ่ายไม่ไหวเลย
พรุ่งนี้ย้ายฟิสิกส์มาไว้เช้า
```

**กฎการ parse**

- บรรทัดที่ขึ้นต้นด้วย `- [ ]` หรือ `- [x]` คือรายการ
- `[h:mm]` ท้ายบรรทัดคือเวลาที่โฟกัสสะสม — ไม่มีวงเล็บ = ยังไม่มีเวลา
- `---` บรรทัดเดี่ยวคือตัวคั่น ทุกอย่างใต้เส้นคือ journal (free text)
- ไม่มี frontmatter — ชื่อไฟล์คือวันที่อยู่แล้ว
- ไฟล์ต้องอ่านรู้เรื่องด้วยตาเปล่าใน text editor ธรรมดา นี่คือข้อกำหนด ไม่ใช่ความชอบ

### 2.3 ความละเอียดของเวลา

**หน่วยคือนาที** session ที่สั้นกว่า 1 นาทีถูกทิ้งทั้งหมด
เหตุผล: กำแพงแบ่งระดับเป็นนาทีอยู่แล้ว และการเก็บวินาทีทำให้ไฟล์อ่านยากโดยไม่ได้อะไรกลับมา

### 2.4 เวลาที่นับได้ — นิยามให้ชัด

เวลาสะสมเฉพาะตอนที่ผู้ใช้อยู่ในหน้า `focus` เท่านั้น

| เหตุการณ์ | นับต่อ? |
|---|---|
| แตะจอเพื่อดูเวลา | **นับต่อ** (เป็นการมองผ่านๆ) |
| สลับไปแอปอื่น / ปิดหน้าจอเครื่อง | **หยุดนับ** |
| กลับเข้ามาในแอป | นับต่อจากเดิม |
| กดค้างเพื่อจบ | ปิด session แล้วบวกเวลาเข้ารายการ |

ผลคือตัวเลขที่เก็บไว้เป็น "เวลาที่ไม่ได้ใช้มือถือทำอย่างอื่น" อยู่แล้วโดยธรรมชาติ
ไม่ต้องมีฟิลด์แยกสำหรับ "เวลาสะอาด"

### 2.5 meta.json

```json
{
  "handle": "@jan",
  "friends": ["@ploy", "@nine"],
  "theme": "auto",
  "createdAt": "2026-01-01"
}
```

### 2.6 การซิงก์

- เข้ารหัส **AES-256 ฝั่งผู้ใช้ก่อนส่งออกจากเครื่อง** เซิร์ฟเวอร์อ่านเนื้อหาไม่ได้
- ซิงก์ทีละไฟล์ (`days/YYYY-MM-DD.md`) ไม่ใช่ทั้งก้อน
- ชนกัน (conflict) → เก็บทั้งสองฝั่งเป็น `2026-08-18.md` และ `2026-08-18 (conflict).md`
  ห้าม merge อัตโนมัติ ห้ามทิ้งของฝั่งใดฝั่งหนึ่ง
- **เมตาที่แชร์กับเพื่อนคือ "นาทีต่อวัน" เท่านั้น** เนื้อหาในไฟล์ไม่เคยถูกแชร์

### 2.7 ระดับของกำแพง

| ระดับ | นาที | โทเคนสี |
|---|---|---|
| 0 | 0 | `--lp-wall-0` |
| 1 | 1–59 | `--lp-wall-1` |
| 2 | 60–149 | `--lp-wall-2` |
| 3 | 150–259 | `--lp-wall-3` |
| 4 | 260+ | `--lp-wall-4` |

## 3. หน้าจอทั้งหมด — 8 หน้า

### 3.1 สรุป

| # | id | ชื่อ | ความถี่ | หมายเหตุ |
|---|---|---|---|---|
| 1 | `day` | วัน | ทุกวัน | หน้าแรก |
| 2 | `focus` | โฟกัส | ทุกวัน | เต็มจอ ทับหน้าอื่น |
| 3 | `wall` | กำแพง | สัปดาห์ละครั้ง | ของตัวเองและของเพื่อนใช้หน้าเดียวกัน |
| 4 | `share` | การ์ดแชร์ | นานๆ ครั้ง | 9:16 สำหรับลงสตอรี่ |
| 5 | `add-friend` | เพิ่มเพื่อน | นานๆ ครั้ง | sheet ไม่ใช่หน้าเต็ม |
| 6 | `settings` | ตั้งค่า | นานๆ ครั้ง | |
| 7 | `account` | บัญชีและซิงก์ | ครั้งเดียว | รวมหน้าขายของไว้ในนี้ |
| 8 | `onboarding` | เปิดครั้งแรก | ครั้งเดียว | 3 จังหวะ |

**หน้า 1–3 คือ 95% ของการใช้งาน** ที่เหลือเป็นหน้าที่ผู้ใช้เข้าไม่กี่ครั้งตลอดชีวิตการใช้แอป

> **กฎ:** ห้ามเพิ่มหน้าที่ 9 โดยไม่เอาหน้าใดหน้าหนึ่งออก
> ถ้ามีคนเสนอหน้าใหม่ ให้ถามก่อนว่ามันอยู่ในหน้า `day` ไม่ได้เพราะอะไร

### 3.2 นอกจากนี้มี state ที่ต้องออกแบบแต่ไม่นับเป็นหน้า

- `day` ตอนยังไม่มีข้อมูลเลย (วันแรก)
- `wall` ตอนยังไม่มีเพื่อน
- `focus` ครั้งแรกในชีวิต (คำใบ้ต้องคอนทราสต์ปกติ ดู §4.2)
- สถานะออฟไลน์ / ซิงก์ล้มเหลว

## 4. สเปกรายหน้า

### 4.1 `day` — หน้าวัน

โครงจากบนลงล่าง

1. แถบสถานะ (เวลาเครื่อง + wordmark จางมาก)
2. ลิงก์ `กำแพง` มุมขวาบน — ขนาด micro สีจาง ต้องไม่ดึงสายตา
3. หัววันที่: `‹` · วันที่ (title) + วันในสัปดาห์ (caption) · `›`
4. รายการ (`line` ซ้ำ)
5. ปุ่ม `+ บรรทัดใหม่`
6. เส้นคั่น `———`
7. ช่อง journal — **สูงเต็มพื้นที่ที่เหลือ** เพื่อให้แตะตรงไหนก็เริ่มพิมพ์ได้
8. แถบล่าง: คำใบ้ซ้าย · เวลารวมของวันขวา

**การกระทำ**

| ท่า | ผล |
|---|---|
| แตะช่องติ๊ก | สลับสถานะทำแล้ว |
| แตะข้อความ | แก้ไขข้อความในที่ |
| **กดค้าง 560ms ที่แถว** | เข้าหน้า `focus` (ยกเว้นตอนกำลังแก้ข้อความบรรทัดนั้นอยู่) |
| ปัดซ้าย/ขวา | เปลี่ยนวัน |
| แตะ `+` | เพิ่มบรรทัดว่างแล้วโฟกัสเคอร์เซอร์ทันที |

**ระหว่างกดค้าง** ต้องมีแถบพื้นสี `--lp-rule-soft` ไหลจากซ้ายไปขวาเต็มแถวใน 560ms
แบบ `linear` ถ้าปล่อยก่อนหรือขยับนิ้วเกิน 8px ให้ยกเลิกทันที

**ห้ามเลื่อนไปวันอนาคต** — `›` ตายเมื่ออยู่ที่วันนี้

### 4.2 `focus` — หน้าโฟกัส

- พื้นหลัง `#000000` เท่านั้น ไม่ใช่เทาเข้ม (บน OLED คือพิกเซลดับจริง)
- **ไม่มีตัวเลขนับ ไม่มีวงกลม ไม่มีแถบความคืบหน้า**
- บนสุดแสดงชื่อสิ่งที่กำลังทำ จางลงหายไปใน 2.6 วินาที
- ล่างสุดคำใบ้ "แตะเพื่อดูเวลา / กดค้างเพื่อจบ" จางลงหายไปพร้อมกัน
- **แตะ 1 ครั้ง** → เวลาโผล่มาแบบ display แล้วจางหายใน 1.8 วินาที
- **กดค้าง 720ms** → จบ session (นานกว่าตอนเริ่มโดยตั้งใจ กันการจบโดยบังเอิญ)
  ระหว่างกดค้างมีเส้น 2px ไหลที่ขอบล่าง

> **ครั้งแรกในชีวิตที่เข้าหน้านี้** คำใบ้ต้องใช้คอนทราสต์ปกติ (ไม่จาง) และค้างไว้จนกว่าจะจบ session แรก
> หลังจากนั้นค่อยหรี่ถาวร — ไม่งั้นผู้ใช้จะหาทางออกไม่เจอ

**เมื่อจบ session** (§4.3)

### 4.3 การส่งต่อไปที่ journal — active recall

นี่คือกลไกที่แยก Lapse ออกจากคู่แข่ง และมันไม่ต้องใช้หน้าจอใหม่เลย

เมื่อจบ session และเวลามากกว่า 0 นาที:

1. บวกเวลาเข้ารายการนั้น แล้วแสดง toast `+ NN นาที`
2. เลื่อนหน้า `day` ลงไปที่ช่อง journal
3. ไฮไลต์ช่อง journal สั้นๆ (1.4 วินาที)
4. **โฟกัสเคอร์เซอร์เข้าช่อง journal อัตโนมัติ** ที่ท้ายข้อความ
5. เปลี่ยน placeholder เป็น `จำอะไรได้บ้างจาก "<ชื่อรายการ>" — เขียนมั่วๆ ก็ได้`
6. ถ้ามีข้อความเดิมอยู่แล้วให้ขึ้นบรรทัดใหม่ก่อน

placeholder กลับเป็นค่าเริ่มต้น (`วันนี้เป็นยังไงบ้าง`) เมื่อเปลี่ยนวัน

### 4.4 `wall` — กำแพง

- หัว: `@handle` + ปี · ใต้ลงมา `NNN ชั่วโมง · NN วัน ในปีนี้`
- ป้ายเดือน (ข้ามป้ายที่ห่างกันน้อยกว่า 3 คอลัมน์ ไม่งั้นชนกัน)
- ตาราง: คอลัมน์ละสัปดาห์ 7 แถว ช่อง 7px เว้น 2px เริ่มจากวันอาทิตย์
- แถบอธิบายระดับ `น้อย ▫▫▫▫▫ มาก`
- แผงรายละเอียด: แตะช่องแล้วขึ้นวันที่ + เวลา
  - **ของตัวเอง** → แสดงรายการของวันนั้นด้วย
  - **ของเพื่อน** → แสดงแค่เวลา พร้อมข้อความ *"เห็นได้แค่เวลา — สิ่งที่เขาเขียนเป็นของเขา"*
- รายชื่อเพื่อน: **เรียงตามลำดับที่เพิ่ม ห้ามเรียงตามเวลา** พร้อมแถบ 30 วันล่าสุด
  หัวข้อเขียนกำกับว่า `ไม่มีอันดับ — เรียงตามลำดับที่เพิ่ม`
- แตะชื่อเพื่อน → กำแพงด้านบนสลับเป็นของเขา (ไม่ใช่หน้าใหม่)

**จำกัดจำนวนเพื่อนที่ 30 คน** ความหายากทำให้มันเป็นวงเพื่อนจริง ไม่ใช่ผู้ติดตาม

### 4.5 `share` — การ์ดแชร์

- สัดส่วน 9:16 สำหรับสตอรี่
- มี: กำแพงปีนี้ · handle · ชั่วโมงรวม · wordmark เล็กๆ
- **ไม่มี**: อันดับ การเปรียบเทียบ คำโฆษณา
- นี่คือช่องทางหาผู้ใช้หลัก ต้องสวยพอที่คนอยากโพสต์เอง

### 4.6 `add-friend`

sheet เล็กๆ ไม่ใช่หน้าเต็ม · ใส่ handle หรือสแกน QR · ไม่มีระบบ "ค้นหาคนที่อาจรู้จัก"

### 4.7 `settings`

ธีม (auto/สว่าง/มืด) · handle · **export ทั้งหมด (ฟรีเสมอ)** · ลบข้อมูล · เกี่ยวกับ
ไม่มีอะไรมากกว่านี้

### 4.8 `account`

สถานะซิงก์ · เข้าสู่ระบบ/ออก · ราคาและการอัปเกรด
ราคาไทย: ฿59/เดือน · ฿299/ปี · **฿549 ตลอดชีพ (ตัวหลัก)**
สากล: $2.99 / $17.99 / $34.99 — ตั้งราคาแยกรายประเทศตาม PPP
รองรับ PromptPay/TrueMoney ผ่านเว็บ (ผู้ใช้ส่วนใหญ่ไม่มีบัตรเครดิต)

### 4.9 `onboarding` — 3 จังหวะเท่านั้น

1. เขียนสิ่งที่จะทำวันนี้ 1 บรรทัด
2. กดค้างที่บรรทัดนั้น → เข้าโหมดโฟกัสจริง จบได้ทุกเมื่อ
3. เห็นช่องแรกบนกำแพงติดขึ้นมา

ไม่มีสไลด์อธิบายฟีเจอร์ ไม่ขอสิทธิ์แจ้งเตือน (เพราะไม่มีการแจ้งเตือน) ไม่บังคับสมัครสมาชิก

สรุปข้อที่ผิดบ่อย

- **สอง family:** mono = สิ่งที่เครื่องใส่ (เวลา วันที่ ตัวเลข handle ป้าย) ·
  sans thai = สิ่งที่มนุษย์พิมพ์ (ชื่องาน journal)
- **สามน้ำหนัก:** 300 / 400 / 500 — **ไม่มีตัวหนา** เน้นด้วยขนาดและพื้นที่ว่าง
- **ไม่มีเงา** ระดับชั้นสร้างด้วยเส้น 1px กับพื้นผิว
- **ไม่มีสีแบรนด์** สีเดียวในระบบคือ `--lp-danger` สงวนให้การลบข้อมูลถาวร
- **จังหวะพิธีกรรม:** เริ่ม 560ms · จบ 720ms · ทั้งคู่ `linear`
- ระยะขอบจอ 26px · ฐาน space 4px · พื้นที่กดขั้นต่ำ 44px
- line-height ข้อความไทยห้ามต่ำกว่า 1.8

## 6. สแตกและเหตุผล

### 6.1 ข้อสรุป

**Flutter (Dart) · iOS + Android · ไม่ทำเว็บในเฟสแรก**

### 6.2 ทำไมไม่ใช่ PWA

เคยพิจารณาแล้วและตกไป เหตุผลไม่ใช่ "PWA ไม่ดี" แต่เป็นเพราะกลไกที่นิยาม Lapse
สองอย่างไปตกอยู่ในจุดอ่อนของ PWA บน iOS พอดี

| สิ่งที่ Lapse ต้องการ | สถานะบนเว็บ |
|---|---|
| **haptic ตอนกดค้าง 560ms** | iOS Safari ไม่รองรับ Vibration API เลย · การกดค้างคือกลไกหลักของแอป ถ้าไม่มีแรงสั่นตอบกลับ พิธีกรรมนั้นตายทันที |
| **แยก "จอล็อก" ออกจาก "สลับไปแอปอื่น"** | เว็บมีแค่ `visibilitychange` ซึ่งยิงเหมือนกันทั้งสองกรณี · กฎกันโกงใน §2.4 พึ่งความต่างนี้โดยตรง |
| การถูกค้นเจอในสโตร์ | PWA ไม่อยู่ในสโตร์ ซึ่งเป็นที่ที่นักเรียนหาแอป |

Capacitor ห่อเว็บก็ไม่ได้แก้ข้อแรก เพราะ WebView บน iOS ยังเป็นเอนจินเดิม

### 6.3 ทำไม Flutter ไม่ใช่ React Native

- **Lapse ไม่เคยอยากดูเหมือนแอปเนทีฟ** ทั้งแอปไม่ใช้คอมโพเนนต์มาตรฐานของระบบเลยสักตัว
  ไม่มี nav bar ระบบ ไม่มีปุ่มมาตรฐาน ไม่มีลิสต์ระบบ — ซึ่งลบข้อได้เปรียบหลักของ RN ทิ้ง
- **ความแม่นยำของการเรนเดอร์** Flutter วาดเองทุกพิกเซล ได้ผลเหมือนกันเป๊ะทั้งสองแพลตฟอร์ม
  ดีไซน์ซิสเต็มนี้เข้มมาก (เส้น 1px, ช่อง 7px, ไล่เทา 5 ขั้น, letter-spacing เจาะจง)
  RN สืบทอด text metrics ของแต่ละแพลตฟอร์ม ซึ่งจะเพี้ยนกันเล็กน้อยและต้องไล่แก้สองรอบ
- **UI หนัก ข้อมูลเบา** คือจุดแข็งของ Flutter โดยตรง — แอปนี้แทบไม่มี networking
  แต่มี custom gesture กับ animation ที่ต้องนิ่งที่ 60fps (แถบ hold 560ms แบบ linear)

**เงื่อนไขที่จะทำให้คำตอบพลิกเป็น RN:** ถ้าวันหนึ่งตัดสินใจว่าต้องมีเว็บแอปใช้งานจริง
(ไม่ใช่แค่หน้าขายของ) ให้ย้ายไป React Native + Expo + react-native-web
อย่าใช้ Flutter Web — มันไม่ใช่คำตอบที่ดีสำหรับงานที่เป็นข้อความหนักแบบนี้

### 6.4 กฎการใช้ Flutter ในโปรเจกต์นี้

- **ห้ามใช้ Material/Cupertino widget ที่มีหน้าตาเป็นของตัวเอง**
  (`ElevatedButton`, `AppBar`, `Card`, `ListTile`, `Checkbox` …) — วาดเองทั้งหมด
  ใช้ได้เฉพาะ primitive: `Column` `Row` `Stack` `GestureDetector` `CustomPaint` `EditableText`
- ห้ามพึ่งสีจาก `ThemeData` ของ Material — สร้าง `LapseTheme` จากโทเคนเอง
- state management เอาแบบเบาที่สุดที่พอใช้ ไม่ต้อง Bloc/Riverpod ก็ได้
- เก็บไฟล์ด้วย path_provider ในโฟลเดอร์เอกสารของแอป โครงตาม §2.1
- **haptic:** ครบ 560ms สั่นหนึ่งครั้ง (medium) · จบ session สั่นอีกครั้ง (light)
- **lifecycle:** ต้องแยก "จอล็อกเอง" (นับต่อ) ออกจาก "สลับไปแอปอื่น" (หยุดนับ)
  ใช้ `AppLifecycleState` ร่วมกับสถานะหน้าจอ อย่าใช้ `paused` อย่างเดียวเพราะกำกวม
- **wake lock:** ห้ามบังคับให้จอติดตลอด ปล่อยให้ล็อกตามปกติ — จอดับคือสิ่งที่เราต้องการ

### 6.5 สิ่งที่ต้องทดสอบก่อนเขียนโค้ดจริงสักบรรทัด

1. เรนเดอร์ข้อความไทยจริงจาก journal (มีสระบนซ้อนวรรณยุกต์) ด้วยฟอนต์จริง
   บน iPhone จริงและ Android ราคาถูกจริง — Flutter เคยมีบั๊กตัดคำไทย (issue #107390 ปิดแล้ว)
   แต่ต้องยืนยันเองกับฟอนต์ที่เลือก
2. เรนเดอร์ตารางกำแพง 7px × 245 ช่อง แล้วดูว่าขอบคมและระยะไม่เพี้ยนที่ DPR ต่างกัน
3. จับเวลาแล้วล็อกจอทิ้งไว้ 10 นาที เช็กว่าเวลาที่ได้ตรง (คำนวณจาก timestamp ไม่ใช่นับ tick)

### 6.6 ต้นทุนฝั่งเซิร์ฟเวอร์

ผู้ใช้หนึ่งคนกินพื้นที่ไม่ถึง 400KB ต่อปี (plain text ล้วน)
แสนคนใช้ห้าปี ≈ 180GB ≈ หลักร้อยบาทต่อเดือน
นี่คือเหตุผลที่ขายแบบจ่ายครั้งเดียวตลอดชีพได้อย่างปลอดภัย

### 6.7 เรื่องการจ่ายเงิน

ยังต้องมีเว็บสำหรับ landing page และ checkout (PromptPay / TrueMoney)
เพราะผู้ใช้ส่วนใหญ่ไม่มีบัตรเครดิต — แต่เป็นแค่หน้าเว็บ ไม่ใช่ตัวแอป
ระวังกฎของ Apple เรื่องการลิงก์ออกไปจ่ายเงินนอกสโตร์ ตรวจเงื่อนไขล่าสุดก่อนปล่อย

## 8. ความเสี่ยงที่รู้ตัว

1. **การปลอมเวลาทำได้ง่ายกว่าการปลอม commit** ถ้ากำแพงถูกรู้ว่าปลอมได้ มันจะหมดค่าเป็นสถานะทันที
   บรรเทาด้วยกฎใน §2.4 — ออกจากแอปแล้วหยุดนับ
2. **ตัดอันดับออกแล้วอาจไม่มีเหตุผลให้กลับมาเปิด** YPT ชนะด้วยแรงกดดันทางสังคม
   ทางแก้ที่ยังอยู่ในกรอบ: เอาหน้าวันเก่าของผู้ใช้เองกลับมาให้ดู
3. **ARPU ในไทยต่ำ** ตลาดไทยอย่างเดียวไปไม่ถึงระดับธุรกิจ ต้องมองการขยายออกต่างประเทศตั้งแต่แรก
   (ซึ่งทำได้ เพราะไม่มีเนื้อหาเฉพาะไทยเหลืออยู่ในผลิตภัณฑ์แล้ว)
4. **ชื่อ Lapse ชนกับแอปแชร์รูป Gen Z ที่ระดมทุนไป $30M** — ใช้ไปก่อน แต่ยังไม่ได้ตรวจเครื่องหมายการค้า
